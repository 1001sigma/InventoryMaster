# 数据库字段变更说明

## 变更背景

旧设计中 `ProductBase.di` 字段同时承担主键、外键关联、业务标识三重角色。Excel 导入时，无 DI 的产品被迫将物料编码或哈希值填入 `di` 字段，导致数据污染。

## 核心变更

新增 `productKey` 作为统一关联键，`di` 降级为纯业务字段（可空，仅存真实 GTIN）。

### 关联键生成规则

```kotlin
ProductBase.computeProductKey(di, materialCode)
// 有 DI    → productKey = DI 值
// 无 DI    → productKey = "MCODE:" + materialCode
// 两者皆空 → 抛异常
```

`MCODE:` 前缀防止物料编码与真实 DI 碰撞。

---

## Schema 变更

### ProductBase (product_base 表)

| 字段 | 旧 | 新 |
|---|---|---|
| `di` | `String` (PK, NOT NULL) | `String?` (可空，仅存真实 GTIN) |
| `productKey` | 无 | `String` (PK, NOT NULL) — 新增主键 |

### StockRecord (stock_records 表)

| 字段 | 旧 | 新 |
|---|---|---|
| `di` | `String` (FK → ProductBase.di) | **已删除** |
| `productKey` | 无 | `String` (FK → ProductBase.productKey) |

### 索引变更

- `["sessionId", "di", "batchNumber", "location"]` → `["sessionId", "productKey", "batchNumber", "location"]`
- `["di"]` → `["productKey"]`

### 数据库版本

`version = 3` → `version = 4`

## 代码变更范围

| 层级 | 文件数 | 关键变更 |
|---|---|---|
| Entity | 3 | ProductBase / StockRecord / StockRecordCombined |
| DAO | 2 | ProductDao / StockRecordDao — 方法改名 + SQL JOIN/WHERE 更新 |
| Model | 1 | ProductConflict — `di` → `productKey` |
| DTO | 1 | SyncModels — DTO 新增 `productKey`，保留 `di` 兼容 |
| Repository | 2 | 接口 + 实现 — 所有方法签名和逻辑适配 |
| Sync | 4 | FullUpload / FullDownload / IncrUpload / IncrDownload Strategy |
| ViewModel | 1 | InventoryViewModel — 搜索/冲突/选择/删除逻辑适配 |
| UI | 6 | InventoryScreen / Dialogs / StockRecordItem / ProductConflictScreen / ProductManagerScreenNav / InventoryMainViewModel |
| Excel | 1 | ExcelUtils — `findDi` 三段式 hack 替换为 `computeProductKey()` |
| DB Config | 1 | AppDatabase — 版本号升级 |

## 接口方法对照

| 旧方法 | 新方法 |
|---|---|
| `getProductByDi(di)` | `getProductByKey(productKey)` |
| `deleteProductByDi(di)` | `deleteProductByKey(productKey)` |
| `deleteProductsByDi(diList)` | `deleteProductsByKey(productKeyList)` |
| `getRecordsByDi(sessionId, di)` | `getRecordsByKey(sessionId, productKey)` |
| `getRecordsByUdi(sessionId, di, batch)` | `getRecordsByUdi(sessionId, productKey, batch)` |
| `findExistingRecord(sessionId, di, ...)` | `findExistingRecord(sessionId, productKey, ...)` |

## 不受影响的模块

- **batchscanner** — 使用独立的 `InventoryRecord` / `TargetItem` 模型，不依赖 Room Entity
- **Gs1Parser** — 扫码解析 UDI 码，与数据库无关
- **ProductJsonUtils** — 基于 Gson 序列化，字段名自动适配

## 使用示例

```kotlin
// 导入 Excel 时
val productKey = ProductBase.computeProductKey(
    di = rawDi.ifBlank { null },
    materialCode = rawMatCode.ifBlank { null }
)

// 创建产品
ProductBase(
    productKey = productKey,  // 关联键
    di = rawDi.ifBlank { null },  // 真实 DI（可为空）
    // ...
)

// 创建库存记录
StockRecord(
    productKey = productKey,  // 关联产品库
    // ...
)

// 查询产品信息
val product = repository.getProductByKey(productKey)
val realDi = product?.di  // String?，仅在有 GTIN 时非空
```
