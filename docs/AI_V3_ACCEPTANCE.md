# AI 助手 v3 一期验收测试题集

> 配套《AI_V3_REDESIGN.md》§8 第一期验收标准：**Qwen / DeepSeek / NVIDIA 免费模型各跑一遍本题集，零 400、零死循环、零卡死。**
> 每题标注了考察点——失败时对照考察点定位是哪层回归。

## 0. 测试前准备

1. **数据**：建一个盘存任务并录入至少 8-10 条记录，覆盖：近效期（30 天内到期）≥2 条、已过期 ≥1 条、空批号 ≥1 条、不同库位 ≥3 个、不同厂家 ≥2 个。没有现成数据就手工录，5 分钟的事，但缺了它近效期/异常题就没法验。
2. **服务商**：三个服务商都配好 Key。Qwen 用 `qwen-plus`，DeepSeek 用 `deepseek-chat`。
3. **NVIDIA 特别注意**：免费模型里有一部分**不支持** Function Calling。先勾选"支持工具调用"测一轮；如果 A-1 就出现模型把工具名/JSON 打印在聊天里或答非所问，进编辑弹窗**取消勾选**再测——这走的是 JSON 文本协议路径，也是本题集要覆盖的分支。
4. **抓日志（可选但强烈建议）**：电脑连手机 `adb logcat -s InventoryAiAgent CloudAiService ConversationMemory`，报错时日志能直接定位。

## A. 基础查询（考察 query_records 结构化参数）

| # | 问题 | 考察点 | 结果 |
|---|------|--------|------|
| A-1 | 现在库里一共多少条库存记录？ | 无条件 count 聚合 | ☐ |
| A-2 | 查一下注射器还有多少库存 | product_keyword 模糊匹配 | ☐ |
| A-3 | 未来 30 天内到期的产品有哪些？ | expiry_within_days（不含已过期） | ☐ |
| A-4 | 2026-12-31 之前过期的产品列出来 | expiry_before：**模型直接传 ISO 日期**，App 换算时间戳 | ☐ |
| A-5 | 当前任务里 A-01 库位有哪些记录？ | session_id 自动注入 + location | ☐ |

**判读**：A-4 是 v2 的高频错误点（旧版要求模型心算 13 位时间戳）。日期错了 = 回归。
A-3 注意语义：已过期的**不该**出现在"未来 30 天内到期"里，如果出现说明上下界拼接有 bug。

## B. 聚合分组

| # | 问题 | 考察点 | 结果 |
|---|------|--------|------|
| B-1 | 按库位统计当前任务每个库位多少条记录 | group_by + count，结果按数量倒序 | ☐ |
| B-2 | 当前任务各厂家的数量合计是多少？ | group_by + sum_quantity | ☐ |

**判读**：返回应该是"库位/厂家 → 数量"的表格，不该出现内部字段名（如 productKey、sessionId）。

## C. 跨任务与多轮工具链（考察 list_sessions + 连续调用）

| # | 问题 | 考察点 | 结果 |
|---|------|--------|------|
| C-1 | 系统里现在有哪些盘存任务？ | list_sessions 工具 | ☐ |
| C-2 | 任务 1（换成真实存在的另一个任务 ID）里的近效期产品有哪些？ | 两轮工具链：先查任务列表再带 session_id 查询 | ☐ |

**判读**：C-2 若模型直接编数据不调工具 = 工具调用回归；若循环调用同一工具 3 次 = 死循环防护该生效并给出"请换一种问法"提示（这也算**通过**，不算卡死）。

## D. 其余工具

| # | 问题 | 考察点 | 结果 |
|---|------|--------|------|
| D-1 | 帮我分析一下当前任务有什么异常 | analyze_abnormal（5 类规则） | ☐ |
| D-2 | 生成当前任务的盘点总结 | generate_summary | ☐ |
| D-3 | 查一下 <某个真实 DI 码> 这个产品的详情 | get_product_detail | ☐ |
| D-4 | 跳转到第 2 条记录 | execute_ui_action → **应弹确认框** → 点执行后跳转 | ☐ |

**判读**：D-4 必须先弹"确认执行操作"对话框（CONFIRM 权限）；30 秒不点应自动按取消处理。点"取消"时 AI 应收到"用户拒绝"并礼貌收尾，不崩。

## E. 多轮记忆（考察轮次记忆 + 裁剪）

| # | 问题 | 考察点 | 结果 |
|---|------|--------|------|
| E-1 | （接着 A-2 问）刚才那个产品，批号是多少？ | 上一轮工具结果仍在记忆里 | ☐ |
| E-2 | 连续随意追问 8-10 轮（混合 A/B 类问题） | 超过 10 轮窗口触发裁剪，**不得出现 400 报错** | ☐ |

**判读**：E-2 是 v3 一期最核心的回归题——旧版裁剪会拆散 tool 配对导致整段对话 400 挂掉。聊天里若出现"API 错误 400"字样立即记录。

## F. 防御与边界

| # | 问题 | 考察点 | 结果 |
|---|------|--------|------|
| F-1 | 帮我查一下 abc' OR 1=1 -- 的库存 | 注入尝试：应正常返回空结果，绝不崩库 | ☐ |
| F-2 | 2026 年 2 月 30 日之前过期的产品 | 非法日期：应提示参数错误，不闪退 | ☐ |
| F-3 | 今天天气怎么样？ | 角色约束：礼貌引导回库存话题 | ☐ |
| F-4 | 查一下批号 ZZZZZ999 的记录（不存在的） | 空结果：如实说没查到，不编数据 | ☐ |

## G. 异常路径（手工操作，非提问）

| # | 操作 | 预期 | 结果 |
|---|------|------|------|
| G-1 | 生成回答中途点"停止"按钮（发送键位置） | 立即停止，出现"（已停止本次回答）"，**之后继续提问正常** | ☐ |
| G-2 | 关掉 Wi-Fi/流量后发消息 | 快速出现"网络连接失败"错误卡片（不用等 3 分钟） | ☐ |
| G-3 | 把 API Key 改错后发消息 | "API Key 无效或已过期" | ☐ |
| G-4 | 未配置任何服务商时进入聊天页 | 占位提示"请先在设置中配置 AI 服务" | ☐ |

**判读**：G-2 计时感受——v2 要 3 分钟才报错，v3 应在几十秒内（最长 90 秒超时）给出明确提示。

## 通过标准

- A-F 全部 20 题在三家中：**零 400、零死循环卡死、零闪退**；
- 工具调用行为正确（该调工具时调、不把工具名/JSON 打印给用户、不编造数据）；
- G 组 4 项全部符合预期；
- 某家服务商个别题答得笨（比如表述啰嗦）**不算失败**——一期验收的是链路可靠性，不是模型智商。
